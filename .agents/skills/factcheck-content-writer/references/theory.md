# Content Writer Skill — 이론 레퍼런스

이 문서는 스킬의 배경 이론과 상세 예시를 담는다.
주 파이프라인은 SKILL.md에 있다.

---

## 왜 "읽고 싶은 글"이 따로 존재하는가

읽기는 비용이다. 독자는 무의식적으로 계산한다:

  읽을지 말지 = 기대 보상 - 예상 노력

기대 보상이 충분히 크지 않으면 스크롤을 넘긴다.

### 6가지 보상 유형

  보상 유형    | 트리거                      | 이 프로젝트 예시
  놀라움       | 내가 믿던 게 틀렸다         | "LLM이 curl 취약점을 못 찾는다"
  분노         | 누군가가 나를 속였다        | "바이트댄스 '오픈소스' — 사실은 가중치 비공개"
  자기이익     | 돈/시간이 절약된다          | "토큰 85%가 낭비된다 — 이렇게 막았다"
  사회적화폐   | 공유하면 내가 똑똑해 보인다 | "다들 우버 AI 얘기 틀리게 알고 있음"
  공감         | 나도 이 상황을 겪었다       | "ChatGPT 또 죽었지? 실제 연쇄 장애 구조"
  FOMO         | 모르면 뒤처진다             | "지금 AI 업계 모두가 잘못 이해하는 것"

현재 도시에(dossier) 훅들의 문제:
이 6가지 보상 중 어느 것도 명시적으로 트리거하지 않는다.
결론을 먼저 말해버려서 긴장감이 사라진다.

## TENSION-FIRST 파이프라인 상세 다이어그램

`
INPUT: dossier metadata.json
  - verdict
  - portfolio_story.the_hook
  - portfolio_story.marketing_hype_anatomy
  - portfolio_story.engineering_takeaways
  - curation.viral_metric
  - community_signals[]
         │
         ▼
┌─────────────────────────────────────────────────────────────┐
│ STEP 1: GATE                                                │
│                                                             │
│  G1: 갭 있는가? ──NO──► 소재 교체                          │
│         │                                                   │
│        YES                                                  │
│         │                                                   │
│  G2: 바이럴 됐는가? ──NO──► 추가 리서치 or 소재 교체       │
│         │                                                   │
│        YES                                                  │
│         │                                                   │
│  G3: 행동이 달라지는가? ──NO──► 소재 교체                  │
│         │                                                   │
│        YES                                                  │
└───────────────────────┬─────────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────────────────┐
│ STEP 2: 독자 정의                                           │
│                                                             │
│  → "지금 [문제]를 겪는 [직군]"을 한 문장으로 쓴다         │
│  → 이 사람이 이미 믿고 있는 것을 적는다                   │
└───────────────────────┬─────────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────────────────┐
│ STEP 3: THE TWIST 추출                                      │
│                                                             │
│  소스: marketing_hype_anatomy vs engineering_takeaways      │
│  형식: "[믿음] → 실제론 [다른 것]"                         │
│  출력: 반전 한 줄                                           │
└───────────────────────┬─────────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────────────────┐
│ STEP 4: TENSION-FIRST 초안                                  │
│                                                             │
│  A │ TENSION  ─── 독자 공감 상황 / 질문 (결론 없음)        │
│  B │ TWIST    ─── Step 3의 반전 한 줄 + 숫자 하나          │
│  C │ EVIDENCE ─── 직접 확인한 가장 구체적인 사실           │
│  D │ IMPLICATION ─ 열린 질문 (결론형 금지)                  │
└───────────────────────┬─────────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────────────────┐
│ STEP 5: 체크리스트                                          │
│                                                             │
│  C1: "나"가 있는가?            ──NO──► PART A 재작성       │
│  C2: 결론을 미리 말하지 않았나? ──NO──► PART A 재작성       │
│  C3: 숫자 2개 이하인가?         ──NO──► 숫자 줄이기         │
│  C4: A+B 합쳐 140자 이내인가?  ──NO──► 문장 압축           │
│  C5: D가 열린 질문인가?         ──NO──► PART D 재작성       │
│         │                                                   │
│       ALL YES                                               │
└───────────────────────┬─────────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────────────────┐
│ STEP 6: 포맷별 출력                                         │
│                                                             │
│  Threads 캡션  ─ A + B + C + D + #태그                     │
│  카드훅        ─ A만 (4줄 이내, 20자/줄)                   │
│  뉴스레터      ─ A→B→C→D 확장 버전                        │
│  퀴즈 JSON     ─ claim=A, explanation=B+C, answer=D요약     │
└─────────────────────────────────────────────────────────────┘
`

## Before / After 예시 — 전체 5개 케이스

### Case 1: Spotify Claude Code Token Shunt

BEFORE (현재 도시에 훅):
  "코딩 에이전트가 소모하는 토큰의 85~90%는 코드가 아니라
  무의미한 터미널 빌드/린트 에러 로그 덤프에서 발생함."

문제:
  - 수동태 종결 ("발생함")
  - 독자와 연결점 없음
  - 결론이 먼저 나와서 긴장감 소멸

AFTER (파이프라인 적용):
  A [긴장]: "Claude Code 쓰는데 왜 이렇게 토큰이 빨리 닳지?"
  B [반전]: "Spotify가 뜯어봤더니, 코딩에 쓰이는 건 15%뿐이었다."
  C [증거]: "나머지 85%? 터미널이 뱉는 에러 로그 쓰레기."
  D [질문]: "필터 하나 끼웠더니 45,000 토큰 → 4,200 토큰.
             그럼 지금 당신 에이전트는 어디서 낭비 중인가?"

Threads 캡션 최종:
  Claude Code 쓰는데 왜 이렇게 토큰이 빨리 닳지?

  Spotify가 뜯어봤더니, 코딩에 쓰이는 건 15%뿐이었다.

  나머지 85%? 터미널이 뱉는 에러 로그 쓰레기.

  필터 하나 끼웠더니 45,000 토큰 → 4,200 토큰.
  그럼 지금 당신 에이전트는 어디서 낭비 중인가?

  #AI팩트체크 #ClaudeCode #토큰절감

### Case 2: Uber Software Factory PR 70%

BEFORE:
  "단순한 코파일럿 수준을 넘어, PR 70%를 에이전트가 주도하고
  2,400만 노드 전사 지식 그래프로 검색 시간을 20분에서 38초로
  96.8% 단축한 우버의 차세대 소프트웨어 공장 실측."

문제:
  - 한 문장에 정보 5개
  - 숫자 홍수 — 아무것도 기억 안 남음
  - 누구를 위한 글인지 모름

AFTER:
  A: "우버 PR의 70%는 이미 AI가 쓴다. 그런데 인건비 절감이 목적이 아니었다."
  B: "에이전트한테 정보 찾으라고 했더니 20분 걸리고 3번 틀렸다."
  C: "지식 그래프 연결하니까 38초에 맞았다."
  D: "그럼 지식 그래프 없는 에이전트는 지금 얼마나 헤매고 있는 건가?"

### Case 3: ByteDance CUDA Agent

BEFORE:
  "중국이 엔비디아의 10년 독점을 무너뜨릴 오픈소스 CUDA AI를
  내놓았다는 자극적 헤드라인의 달콤함과, 그 이면에 감춰진
  '모델 비공개(비오픈소스)' 및 '엔비디아 락인 심화'라는
  역설적 엔지니어링 현실."

문제:
  - "달콤함", "역설적" — 과도한 수식어
  - 결론(엔비디아 락인)이 훅에 이미 나옴
  - "모델 비공개"가 괄호 안에 묻혀있음

AFTER:
  A: "17.9만 명이 RT했다. '중국이 CUDA를 오픈소스로 박살냈다'고."
  B: "근데 모델 가중치는 공개 안 했다."
  C: "재현하려면 H100이 128개 필요하다."
  D: "그럼 이게 오픈소스인가, 마케팅인가?"

## 숫자 선택 원칙

전체 수치가 많을 때 딱 하나를 고르는 기준:
  - 가장 극단적인 것 (90% 절감 > 30% 개선)
  - 대비가 명확한 것 (20분 vs 38초 > 96.8% 단축)
  - 독자가 직감적으로 이해하는 것 (4,200 토큰 > 90.6% 절감)

| 케이스 | 전체 수치 | 선택할 단 하나 |
|:---|:---|:---|
| Spotify | 45k→4.2k tok, 90.6%, +18% | "45,000 토큰 → 4,200 토큰" |
| Uber | PR 70%, 2400만 노드, 20분→38초, 3600 스킬 | "20분(오답) → 38초(정답)" |
| ByteDance | 2.11배, 98.8%, 179만 뷰 | "17.9만 뷰, 근데 가중치 비공개" |
| ChatGPT | +466%, 168 HN Points | "응답 1.2초 → 6.8초" |
| curl | CVE 6개, LLM 0건 | "LLM 0건 vs 특화도구 6건" |
