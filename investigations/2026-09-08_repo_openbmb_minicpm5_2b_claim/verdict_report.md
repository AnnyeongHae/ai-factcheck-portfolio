# 심층 팩트체크 검증 보고서: OpenBMB MiniCPM5-2B: 2B 온디바이스 파라미터로 8B급 추론·131K 문맥 처리 주장의 실체 검증

## 1. 검증 대상 개요
- **대상 모델**: OpenBMB MiniCPM5-2B (Dense 2.4B Parameter SLM)
- **원천 출처**: [X Trending Topic](https://x.com/i/trending/2096982064872767994) / OpenBMB Official Hub
- **주요 주장**: 2B 파라미터 소형 모델이 131K 컨텍스트를 지원하며, <think> 듀얼 추론 모드를 통해 Llama-3.1-8B 및 Qwen-2.5-7B를 수학/코딩에서 능가하고 스마트폰에서 완벽하게 온디바이스 구동된다.

## 2. 실측 검증 결과 요약
- **최종 판정**: **절반의 사실 (HALF_TRUE)** (신뢰도 68.5%)
- **핵심 근거**:
  1. **합성 데이터 증류의 성과 (참)**: WSD 스케줄러와 대형 교사 모델(DeepSeek-R1 등)의 추론 경로 학습을 통해 2B급 밀집 모델 중 GSM8K/MATH 벤치마크 점수는 최상위권 달성.
  2. **추론 지연 시간의 역설 (한계)**: <think> 모드 활성화 시 답변 1건당 800~1,500개의 내부 독백 토큰을 생성하여, 모바일 환경(초당 15~25토큰)에서 1건 처리에 40~60초가 소요되어 실시간 UX 붕괴.
  3. **131K 문맥의 메모리 모순 (과장)**: 131K RoPE 처리는 가능하나, 131K 입력 시 KV 캐시만 약 3.2GB를 차지하여 1.5GB 모델 가중치보다 커짐. 8GB 이하 모바일 폰에서는 즉각 OOM 발생.

## 3. 엔지니어링 실무 권고
- **권장 워크플로우**: 온디바이스 실시간 질의응답 시에는 `No-Think` 모드 및 `8K~16K` 문맥으로 제한 구동할 것.
- **다단계 추론 필요 시**: 배터리 및 레이턴시 제약이 없는 데스크톱/서버 환경에서만 `<think>` 모드를 활성화할 것.
