## 1. 개요 및 바이럴 클레임 분석
Threads(@k1utch_ai)에서 '이미지 모델 8개와 영상 모델 24개를 단 한 칸의 프롬프트 바에서 제어하고, 각 모델의 고유 설정창을 그대로 옮겨놓은 무료 오픈소스 스튜디오 OpenHiggsfield가 별 1,200개를 넘겼다'는 포스트가 공유되었습니다. 이미 인박스에 수집된 깃허브 저장소(`wide-trace/open-higgsfield`)의 타입스크립트 소스코드를 감사하고, 모델 파라미터 동적 매핑, 브라우저 스토리지(IndexedDB) 보존, API 비용 구조를 정밀 검증했습니다.

본 팩트체크 도시에에서는 해당 기술의 원본 소스코드, 벤치마크 실측 수치, 아키텍처 다이어그램 및 대안 비교를 통해 실무적 실체와 엔지니어링 트레이드오프를 규명했습니다.

## 2. 공학적 실측 검증 결과

### 2.1 주요 사실 및 강점
1. **동적 파라미터 모핑(Dynamic Parameter Morphing)**: 모델 선택 드롭다운에 따라 종횡비(16:9, 9:16), FPS, 재생 시간(5s, 10s), 오디오 생성 토글 등 각 공급자 스키마에 맞는 위젯이 실시간 동적 렌더링. 2. **클라이언트 사이드 지속성 (Zero Backend Storage)**: 사용자의 생성물, 프롬프트 히스토리(최대 60개), API 키가 외부 서버에 전송되지 않고 브라우저 로컬 스토리지 및 IndexedDB에만 암호화 저장되어 프라이버시 보호. 3. **배치 추론(Batch Inference) 지원**: 동일 프롬프트에 대해 최대 4개 시드를 병렬 쿼리하여 결과 비교 가능. 4. **원클릭 언두(Undo) 및 복원**: 실수로 삭제한 결과물을 6초 이내에 복원하는 스택 기반 캐시 구축.

### 2.2 현실적 한계 및 마케팅 왜곡 (Hype Anatomy)
'스튜디오가 완전히 공짜'라는 표현은 **자체 소프트웨어 구독료($0)와 웹 프론트엔드가 무료라는 뜻**이며, 실제 이미지와 비디오 생성 연산은 **사용자 본인의 API 키(Fal.ai, Replicate, HuggingFace 등)를 등록하는 BYOK(Bring Your Own Key) 방식**으로 실행됩니다. 따라서 AI 생성 자체에 비용이 전혀 안 드는 것은 아니지만, 중간 수수료나 플랫폼 마진 없이 클라우드 원가(Raw API Cost)로만 다양한 모델을 전환하며 쓸 수 있다는 점에서 매우 솔직하고 유용한 오픈소스입니다.
